# Architect Handoff: Docker End-to-End Testing Pipeline

## Objective
Design and implement an end-to-end integration testing loop utilizing the standard `docker-compose.yml`. The test suite should orchestrate docker startup, schema initialization, gap-fill queuing, and websocket streaming, and finally validate the resulting TimescaleDB tables for data continuity.

## Scope Boundaries
- **In Scope**:
  - A test orchestration script (`tests/e2e/test_docker_integration.py` or equivalent test file).
  - Logic to stand up `db`, `broker`, `worker-streams`, and `worker-queue`.
  - Database schema alignment (e.g., executing `schema.sql` inside the `db` container or from the host).
  - Initialization health checks for Postgres (TimescaleDB) and Valkey.
  - Assertions querying TimescaleDB to prove gap-fill and live ingestion data rows exist.
  - Debugging instructions and logging outputs for failure modes.
- **Out of Scope**:
  - Creating a separate `docker-compose.test.yml`.
  - Modifying core ingestion code (`flipper_agent/ingestion/`).
  - Altering the base `.yaml` configuration limits specifically for this branch, as the user stated reduced limits are already present.

## Affected Symbols, Modules, and Execution Flows
- **Modules**: `tests/e2e/`
- **Infrastructure**: Interactions with `docker-compose up/down` within the testing wrapper or fixture.
- **Execution Flows**: Pytest execution pipeline -> Docker Orchestration -> Polling Health Checks -> Schema Initialization -> Data Production (Workers) -> Data Assertions -> Teardown.

## Data Contracts or Interfaces
- Test queries should utilize standard TimescaleDB interfaces (e.g., asyncpg or `psycopg`) via the mapped `5432` container port.
- Test script must respect the `POSTGRES_USER`, `POSTGRES_PASSWORD`, and `POSTGRES_DB` values as defined in `docker-compose.yml`.

## Implementation Order
1. **Docker Pytest Fixture Wrapper**: Implement a fixture (e.g. in `conftest.py` or the test file itself) to run `docker-compose down -v` to ensure a clean slate, followed by `docker-compose up -d db broker worker-streams worker-queue`. 
2. **Health Checks**: Implement iterative waiting loops (retries with backoff) using tools like `pg_isready` for Postgres and ping for Valkey.
3. **Database Seeding**: Execute the schema initialization script inside the DB container once the DB is ready (e.g., `docker-compose exec -T -e PGPASSWORD=flipperpass db psql -U flipper -d flipper_db -f /path/to/schema.sql`).
4. **Validation Test**: Write a polling query loop against target database tables (e.g., ticks or aggregated candles) that waits for row counts to increase > 0 within a predefined timeout, proving the stream and gap-fill flows are functioning.
5. **Teardown & Artifacts**: Add cleanup logic that automatically captures and outputs `docker-compose logs` if an assertion fails prior to executing the `down` teardown.

## Acceptance Criteria
- Running `pytest tests/e2e/test_docker_integration.py` reliably brings up all necessary services.
- Container health readiness is verified prior to validation queries.
- Data propagation into TimescaleDB succeeds and is verifiable through SQL select row counts.
- `docker-compose.yml` is used directly without alternative overrides.
- Failure automatically dumps docker logs to stdout/stderr.

## Validation Checklist
- [ ] TimescaleDB initializes cleanly.
- [ ] Valkey initializes and handles broker connections.
- [ ] `worker-streams` starts streaming successfully.
- [ ] `worker-queue` processes gap-fill logic properly.
- [ ] Pytest query loop succeeds within the configured latency timeout without false negatives.

## Explicit Non-Goals
- Do not build a completely separate Docker network test override.
- Do not implement mock streams in E2E; rely on the real execution container configurations.

## Debugging Guide
To debug E2E test failures:
1. **View Container Logs**: Extract container logs for the queue or streams utilizing `docker logs <project>-worker-streams-1` and `docker logs <project>-worker-queue-1`.
2. **Interact with the DB**: For inspecting DB state manually before teardown, pause the test test loop (e.g., setting a breakpoint) and connect: `docker exec -it <project>-db-1 psql -U flipper -d flipper_db`.
3. **Examine Internal Application Logs**: Python logging generated by `logger_utils.py` will appear in the mounted volume `./data/app.log`, which can be examined manually during or after failures.
